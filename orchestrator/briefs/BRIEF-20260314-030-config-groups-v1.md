# BRIEF-20260314-030 — Config Groups (A09)

## Проблема
`Config` — плоский dataclass с 122+ полями без группировки. Это затрудняет
понимание, навигацию и добавление новых параметров.

## Цель
Реструктурировать `Config` в nested groups, сохранив совместимость с:
- пресетами YAML (`profile_io.py`): поля читаются через `load_preset`
- 50+ вызовами `cfg.FIELD` по всей кодовой базе
- `run_quality_gate.py` и CLI-скриптами

## Ограничения
- НЕ менять публичный API пока весь код использует `cfg.FIELD` напрямую.
- Допустимо: добавить group-классы + proxy-свойства на `Config` для обратной совместимости.
- Альтернатива: просто разделить на секции через комментарии + `# --- GROUP ---`,
  без изменения структуры. Это наименее рискованный вариант.

## Рекомендуемый подход (minimal risk)
Вариант 1 (безопасный): Структурировать `config.py` логическими блоками
через комментарии-секции. Не менять типы или имена полей.
- Секции: Model, Tracking, Lock, Night, ROI, Budget, Display, AutoScene

Вариант 2 (с nested): Ввести `@dataclass` группы и добавить `@property`
aliases на верхний уровень Config для обратной совместимости.

## Объём
Средний — 1 сессия. Обязательный тест: все существующие тесты + compileall OK.

## Риск
ВЫСОКИЙ при Варианте 2 (50+ точек вызова). НИЗКИЙ при Варианте 1.
